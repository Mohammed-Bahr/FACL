Coordinate System Transformations

In robotics, Coordinate System Transformations provide the mathematical tools to describe the position and orientation of objects or robot components across different reference frames, and to map coordinates between them

Let's distinguish between them World Frame and Local Frame:

  • World Coordinate System: This is the primary, fixed Reference Frame relative to which we measure. We will denote it as Frame 0.
  • Local Coordinate System: This is a Frame attached to a specific Link and moves with it. For example, Frame 1 is attached to the first Link, and Frame 2 is attached to the second Link.

The Position of a point may differ depending on the Frame you are measuring relative to, even though the point itself hasn't changed.And This is completely normal if you think about it.

Why IK is unavoidable in control

  • Sensing the current pose: Joint encoders give 𝑞, and FK gives the hand pose 𝑝. Other sources can also give the pose:
    • GPS works outdoors but has errors of several metres, so it's weak for small robots.
    • Indoor Wi-Fi signal strength (RSSI): each position has a distinctive "fingerprint" of signal strengths from several access points (stronger near a router, weaker far away). A regression model maps the fingerprint to a position.
  • Commanding the robot: In feedback control you compare the measured pose with the target pose to get an error in task space.
    • The robot only accepts joint commands, so you must convert the target to joint angles.
So FK is used to know where you are and IK is used to know what to command.

Differential (velocity) kinematics

So far, we have been dealing with Position and Orientation. But when we want to Control the robot, it's not enough to know where it is. We must also know:

  • How fast is it moving?
  • If we change a Joint Angle by a small amount, how much will the End Effector move?
  • If we want the End Effector to move at a certain velocity, what velocities should we move the Joints at?

Here comes the concept of Differential Kinematics: describes the relationship between joint velocities ˙𝑞 and the resulting linear and angular velocities of the end-effector.

This linear velocity relationship is governed by a configuration dependent matrix called the **Jacobian Matrix:

Derivation

Main Types of Jacobians

Depending on how we represent orientation and coordinate frames, there are three common formulations:

  1. Coordinate / Analytic Jacobian (𝐽𝑎):
    • Obtained by taking direct partial derivatives of the forward kinematics vector function: 𝐽𝑎(𝑞) =𝜕𝑓(𝑞)𝜕𝑞.
    • Simple and intuitive for 2D arms, but in 3D it uses Euler angle derivatives (˙𝜙), which can introduce artificial mathematical singularities (Gimbal Lock).
  2. Space / Geometric Jacobian (𝐽𝑠):
    • Relates joint rates to the true physical spatial twist V𝑠 =[𝜔𝑠𝑣𝑠] ∈ℝ6 expressed in the fixed world frame.
    • Built directly using the physical joint rotation/translation axes in 3D space without needing Euler angle derivatives.
  3. Body Jacobian (𝐽𝑏):
    • Relates joint rates to the body twist V𝑏 =[𝜔𝑏𝑣𝑏] ∈ℝ6 expressed in the moving end-effector frame.
    • Related to the Space Jacobian via the Adjoint transformation: 𝐽𝑏 =[Ad𝑇𝑏𝑠]𝐽𝑠. Both have the exact same rank and singular values.

Worked example: Jacobian of the planar 2-link arm

Position only (𝑚 =2), from the notes.

  1. FK: 𝑥 =𝑙1cos⁡𝜃1 +𝑙2cos⁡(𝜃1 +𝜃2), 𝑦 =𝑙1sin⁡𝜃1 +𝑙2sin⁡(𝜃1 +𝜃2).
  2. Differentiate each output with respect to each joint:

𝐽=⎡⎢ ⎢ ⎢⎣𝜕𝑥𝜕𝜃1𝜕𝑥𝜕𝜃2𝜕𝑦𝜕𝜃1𝜕𝑦𝜕𝜃2⎤⎥ ⎥ ⎥⎦=[−𝑙1sin⁡𝜃1−𝑙2sin⁡(𝜃1+𝜃2)−𝑙2sin⁡(𝜃1+𝜃2)𝑙1cos⁡𝜃1+𝑙2cos⁡(𝜃1+𝜃2)𝑙2cos⁡(𝜃1+𝜃2)]

Column 2 only has an 𝑙2 term because 𝜃2 moves only the second link. Column 1 has both because 𝜃1 moves the whole arm.

Extension (singularity): det𝐽 =𝑙1𝑙2sin⁡𝜃2. So the arm is singular at 𝜃2 =0 or 𝜋, when it is fully stretched or fully folded. There the tip can't move along the arm's own direction, and 𝐽−1 blows up, which is the "infinite values" the lecturer describes. If you also include orientation 𝜙 =𝜃1 +𝜃2, 𝐽 becomes 3 ×2 with an extra row [1 1].

Code

This is Python, and it implements everything above for the 2-link arm. I ran it: the matrix-chain FK matches the closed form, the Jacobian matches finite differences to about 10−10, and the iterative IK converged to the target.

import numpy as np

def Rot(th):                       ## 2D homogeneous rotation
    c, s = np.cos(th), np.sin(th)
    return np.array([[c, -s, 0], [s, c, 0], [0, 0, 1]])

def Trans(a, b):                   ## 2D homogeneous translation
    T = np.eye(3) T[0, 2], T[1, 2] = a, b
    return T

def fk(th1, th2, l1, l2):
    T01 = Rot(th1)                 ## frame1 -> frame0
    T12 = Trans(l1, 0) @ Rot(th2)  ## frame2 -> frame1: rotate, then shift l1 along x1
    p2 = np.array([l2, 0, 1.0])    ## tip in frame 2
    return (T01 @ T12 @ p2)[:2]    ## tip in frame 0 (x, y)

def jacobian(th1, th2, l1, l2):
    s1, c1 = np.sin(th1), np.cos(th1)
    s12, c12 = np.sin(th1 + th2), np.cos(th1 + th2)
    return np.array([[-l1*s1 - l2*s12, -l2*s12],
                     [ l1*c1 + l2*c12,  l2*c12]])

def ik_iterative(target, q, l1, l2, step=0.5, tol=1e-9, max_iter=200):
    """Repeat: small task-space step -> joint step via pseudo-inverse."""
    for _ in range(max_iter):
        err = target - fk(*q, l1, l2)          ## task-space error
        if np.linalg.norm(err) < tol:
            break
        dq = np.linalg.pinv(jacobian(*q, l1, l2)) @ (step * err)  ## dq = J+ dp
        q = q + dq
    return q

def ik_analytic(x, y, l1, l2):
    """Closed form: returns both elbow solutions, or [] if unreachable."""
    c2 = (x*x + y*y - l1*l1 - l2*l2) / (2*l1*l2)
    if abs(c2) > 1: return []
    sols = []
    for th2 in (np.arccos(c2), -np.arccos(c2)):
        th1 = np.arctan2(y, x) - np.arctan2(l2*np.sin(th2), l1 + l2*np.cos(th2))
        sols.append((th1, th2))
    return sols

l1, l2 = 1.0, 0.7
q = ik_iterative(np.array([1.1, 0.8]), np.array([0.3, 0.5]), l1, l2)
print(q, fk(*q, l1, l2))   ## -> reaches (1.1, 0.8)

How it maps to the theory: fk is the chain 𝑇10𝑇21𝑝2. ik_iterative is the differential relation 𝛿𝑞 =𝐽+𝛿𝑝 applied repeatedly with small steps. This is the standard way IK is done on real robots, because the linear approximation only holds locally. The step factor keeps each move small. Near a singularity this loop becomes unstable, which is the problem the lecturer defers to next time.
