Part 1 — Control Loop & the Error Signal

The entire lecture is built around one loop: a reference (what you want) flows through a controller and a plant (motor, joint, robot), a sensor measures the result, and the measurement is subtracted from the reference to form the error. The controller's only job is to process that error and drive the actuator — here the PWM duty cycle 𝛼 — so the error shrinks toward zero. Every equation later in this note is just a mathematical refinement of this single idea.

𝑒(𝑡)=𝑟(𝑡)−𝑐(𝑡)

Symbol Name Job in the loop
𝑟(𝑡) Reference The target you command: desired angle, speed, position. It is the input of the loop.
𝑐(𝑡) Output (measured) What the sensor reports the plant is actually doing at time 𝑡.
𝑒(𝑡) Error The gap 𝑟 −𝑐. The only signal the controller is allowed to act on.
𝑡 Time All three signals are continuous functions of time in this domain.
𝛼 PWM duty cycle The knob the controller turns — the physical control command to the motor driver.

Sign logic (what the error tells the controller to do):

Case Physical meaning Typical motor reaction
𝑒 >0 output is below the target increase PWM 𝛼
𝑒 <0 output is above the target decrease PWM 𝛼
𝑒 =0 on target at this instant hold the current command
  • Negative feedback means the output is subtracted at the summing point (𝑒 =𝑟 −𝑐). It does not mean the output value itself is negative — it only names the sign convention of the comparison.
  • Why feedback is worth the hardware: accuracy (corrects drift), disturbance rejection (compensates load changes), better time response, and it can stabilize a plant that is unstable on its own. Open-loop drift happens because resistance, friction, and magnet strength change with time, so a fixed calibration goes stale — closed-loop re-measures and compensates automatically.
Unity feedback assumption

𝑒 =𝑟 −𝑐 assumes the sensor chain has gain exactly 1, so the measurement can be compared directly with the reference. Every formula in Parts 3–5 inherits this assumption.

Part 2 — Optical Encoder Math

The encoder is the sensor of the loop: it converts mechanical rotation into a digital code a microcontroller can read. Its math answers four questions: how many codes exist, how fine is one step, what angle does a code mean, and how do we get speed out of position samples.

2.1 Codes from tracks

𝑁=2𝑛

Symbol Name Job
𝑛 Number of tracks Each track is read by one photocoupler (LED + phototransistor) and contributes exactly one bit (bright = 1, dark = 0).
𝑁 Distinct codes The number of unique bit patterns = number of sectors the disc divides one revolution into.
How we reached it: 𝑁 =2𝑛

Each track gives one binary digit: 0 or 1.

With 𝑛 independent tracks, a reading is an 𝑛-bit word, and the number of distinct binary words on 𝑛 bits is:

2⋅2⋅…⋅2𝑛 times=2𝑛

Check with 𝑛 =2: the words are 00,01,10,11 → 22 =4 codes, matching the lecture.

2.2 Angular resolution

Δ𝜃=2𝜋𝑁 rad=360∘𝑁

Symbol Name Job
Δ𝜃 Angular resolution The smallest angle change the encoder can distinguish between two neighboring codes. Smaller = finer sensing.
𝑁 Sector count Divides the full circle 2𝜋 (or 360∘) equally; more sectors → smaller steps.
How we reached it: worked example with 3 tracks

With 𝑛 =3 tracks:

𝑁=23=8⇒Δ𝜃=360∘8=45∘

And with only 𝑛 =2 tracks: 𝑁 =4, so Δ𝜃 =360∘/4 =90∘ — exactly the two cases the lecture compares.

2.3 Angle from a code

𝜃=code𝑁⋅2𝜋 rad

Symbol Name Job
code Zero-indexed digital reading Integer from 0 to 𝑁 −1; tells which sector the shaft is currently in.
𝜃 Idealized sector angle The angle of the start of that sector, assuming a known zero reference and consistent code mapping.
What this formula does not tell you

𝜃 here is the idealized sector position, not the exact true angle inside the sector — the true angle can be anywhere within the Δ𝜃-wide sector. That gap is precisely the quantization error: the difference between the real continuous angle and the angle represented by the digital code. Worst case, the true angle sits anywhere in a Δ𝜃-wide sector, so the uncertainty is bounded by the resolution (±Δ𝜃/2 if each code is read as its sector's centre).

2.4 Gearbox effect

𝜃𝑜𝑢𝑡=𝜃𝑚𝑜𝑡𝑜𝑟𝐺

Symbol Name Job
𝜃𝑚𝑜𝑡𝑜𝑟 Motor-shaft angle What an encoder mounted on the motor side sees.
𝜃𝑜𝑢𝑡 Output-shaft angle The angle that actually reaches the load.
𝐺 Gear reduction ratio (𝐺 :1) The motor spins 𝐺 revolutions per 1 output revolution. The gearbox divides angle and speed by 𝐺 while multiplying torque by roughly 𝐺.
How we reached it: gearbox shrinking one encoder step

With 𝐺 =1000 :1, the motor turns 1000 revolutions while the output shaft turns 1.

So one motor-side encoder step of 45∘ appears at the output as:

45∘1000=0.045∘

Practical meaning: mounting the encoder on the motor side of a large reduction gives an effective resolution far finer than the raw Δ𝜃 — the gear ratio divides the step size, not just the speed.

2.5 Estimating speed from position

𝜔𝑘≈𝜃𝑘−𝜃𝑘−1𝑇𝑠

Symbol Name Job
𝜃𝑘 Current angle sample Where the shaft is now (read 𝑘).
𝜃𝑘−1 Previous angle sample Where it was one read earlier (read 𝑘 −1).
𝑇𝑠 Sampling period The (fixed) time between the two reads.
𝜔𝑘 Estimated angular velocity The average speed over the last interval — the slope between two angle samples.
How we reached it: from 𝜔 =𝑑𝜃/𝑑𝑡 to a finite difference

Start from the definition of angular velocity as the derivative of angle:

𝜔(𝑡)=𝑑𝜃𝑑𝑡

A microcontroller cannot measure an infinitesimal 𝑑𝑡. Over a small but finite interval 𝑇𝑠, approximate:

𝑑𝜃→Δ𝜃=𝜃𝑘−𝜃𝑘−1,𝑑𝑡→𝑇𝑠

Substituting gives the backward finite difference:

𝜔𝑘≈𝜃𝑘−𝜃𝑘−1𝑇𝑠

It is literally "distance in angle ÷ time taken" — the slope of the angle samples. Accuracy degrades if 𝑇𝑠 is too large or the speed changes a lot within one interval.

Gray code caveat

Real encoders usually encode sectors in Gray code, where neighboring sectors differ in exactly one bit — so a boundary read can never produce a wildly wrong multi-bit error.

Part 3 — Closed-Loop Transfer Functions

The goal shifts from measuring the motor's angle to controlling it. Working in the Laplace domain (variable 𝑠) turns differential equations into algebra, so we can manipulate the whole loop with fractions. Everything here is built from two building-block equations and one act of substitution.

Symbol dictionary:

Symbol Domain Meaning
𝐻𝑐(𝑠) Laplace Controller transfer function — how the controller maps error to command.
𝐺(𝑠) Laplace Plant transfer function — how the motor/robot responds to the command.
𝑅(𝑠) Laplace Reference input, transformed into the 𝑠-domain.
𝐸(𝑠) Laplace Error signal in the 𝑠-domain.
𝐶(𝑠) Laplace Output of the plant in the 𝑠-domain.
𝑠 Laplace variable Replaces time-domain differential operators with algebra; 𝑠 =0 means "steady state / DC".
𝑀(𝑠) =𝐶/𝑅 ratio Shorthand for the closed-loop transfer function.

Term Job
𝑅(𝑠) What was asked for.
𝐶(𝑠) What came back through the sensor loop.
− The "negative feedback" itself: output is subtracted, never added.

Term Job

3.1 The closed-loop transfer function

𝐶(𝑠)𝑅(𝑠)=𝐻𝑐(𝑠)𝐺(𝑠)1+𝐻𝑐(𝑠)𝐺(𝑠)

Piece Job
Numerator 𝐻𝑐𝐺 The raw amplification of the chain (controller × plant).
Denominator 1 +𝐻𝑐𝐺 The "closed-loop" part — the 1 exists because the output is fed back and subtracted. All system dynamics (poles) live here.
How we reached it: closed-loop transfer function in 4 moves

Step 1 — substitute the error into the forward-path equation, since 𝐸 =𝑅 −𝐶:

𝐶=𝐻𝑐𝐺(𝑅−𝐶)

Step 2 — expand the right-hand side:

𝐶=𝐻𝑐𝐺𝑅−𝐻𝑐𝐺𝐶

Step 3 — collect every term containing 𝐶 on the left:

𝐶+𝐻𝑐𝐺𝐶=𝐻𝑐𝐺𝑅⟹𝐶(1+𝐻𝑐𝐺)=𝐻𝑐𝐺𝑅

Step 4 — divide both sides by 𝑅 (1 +𝐻𝑐𝐺):

𝐶𝑅=𝐻𝑐𝐺1+𝐻𝑐𝐺

Notice the logic: the output appears on both sides because feeding it back is exactly what creates the +1 in the denominator. An open-loop chain would never produce that term.

3.2 The error transfer function

𝐸(𝑠)𝑅(𝑠)=11+𝐻𝑐(𝑠)𝐺(𝑠)

Piece Job
Numerator 1 Error depends only on the reference and the loop — no separate plant path.
Denominator 1 +𝐻𝑐𝐺 Same denominator as the output TF: the loop's stability lives in one place.
How we reached it: error transfer function

Start from the definition of error and divide by 𝑅:

𝐸𝑅=1−𝐶𝑅

Insert the closed-loop result from 3.1:

𝐸𝑅=1−𝐻𝑐𝐺1+𝐻𝑐𝐺=(1+𝐻𝑐𝐺)−𝐻𝑐𝐺1+𝐻𝑐𝐺

The numerator collapses, because the controller–plant product cancels itself:

𝐸𝑅=11+𝐻𝑐𝐺

Bonus insight: a large loop gain 𝐻𝑐𝐺 makes 𝐸/𝑅 small — feedback with muscle naturally suppresses error.

3.3 The characteristic equation — where stability lives

1+𝐻𝑐(𝑠)𝐺(𝑠)=0

Piece Job
Roots of 1 +𝐻𝑐𝐺 =0 The closed-loop poles — the values of 𝑠 where the system's response explodes or decays.
Pole location Decides stability, speed, and oscillation, all at once.
Pole position Consequence
Left half-plane (Re(𝑠) <0) Mode decays like 𝑒𝑝𝑡 with 𝑝 <0 → stable. Further left → faster decay → quicker response.
Right half-plane (Re(𝑠) >0) Mode grows without bound → unstable.
On the imaginary axis Sustained oscillation — the borderline case.
Why the denominator's roots rule everything

Any closed-loop response can be decomposed into terms of the form 𝐾𝑠−𝑝, whose inverse Laplace transform is 𝐾 𝑒𝑝𝑡.

  • If Re(𝑝) <0, 𝑒𝑝𝑡 dies away — the system forgets disturbances and settles.
  • If Re(𝑝) >0, 𝑒𝑝𝑡 grows — the output runs away no matter what the reference asked for.
  • If 𝑝 is complex, 𝑒𝑝𝑡 oscillates at the pole's imaginary part while the real part decides whether the oscillation grows or decays.

Since the poles are exactly the roots of 1 +𝐻𝑐𝐺 =0, solving one equation answers the three exam questions: stable? fast? oscillatory?

3.4 Final value theorem — predicting where it settles

For a unit-step reference, 𝑅(𝑠) =1𝑠:

𝑐𝑠𝑠=lim𝑠→0𝑠𝐶(𝑠)=𝑀(0)𝑒𝑠𝑠=lim𝑠→0𝑠𝐸(𝑠)

Piece Job
𝑐𝑠𝑠, 𝑒𝑠𝑠 Steady-state output and error — the values left after transients die.
lim𝑠→0 Evaluating at 𝑠 =0 = asking about DC / constant behavior.
𝑀(0) The closed-loop DC gain: what the system outputs for a constant input.
How we reached it: 𝑐𝑠𝑠 =𝑀(0)

The output in the 𝑠-domain is the closed-loop TF times the input:

𝐶(𝑠)=𝑀(𝑠)𝑅(𝑠)=𝑀(𝑠)⋅1𝑠

Apply the final value theorem:

𝑐𝑠𝑠=lim𝑠→0𝑠𝐶(𝑠)=lim𝑠→0𝑠𝑀(𝑠)1𝑠=𝑀(0)

The 𝑠 from the theorem cancels the 1/𝑠 of the step — so the final value is simply the closed-loop gain evaluated at zero. The same recipe on 𝐸(𝑠) gives 𝑒𝑠𝑠.

Validity check (never skip it): the theorem is only legal if the closed loop is stable — the limit must exist. On an unstable loop the output never settles, so the formula silently returns a meaningless number.

Part 4 — P Control on an Unstable Plant

This part is a complete worked case study: can a simple proportional controller rescue a plant that is unstable on its own?

Setup:

Plant 𝐺(𝑠) =1𝑠−3 Pole at 𝑠 = +3 — right half-plane → the open-loop motor model diverges like 𝑒3𝑡.
Controller 𝐻𝑐(𝑠) =𝐾𝑝 (pure gain) 𝑢 =𝐾𝑝 𝑒: command proportional to the current error only.

𝐶(𝑠)=𝐾𝑝𝑠−3𝐸(𝑠)=𝐾𝑝𝑠−3[𝑅(𝑠)−𝐶(𝑠)]

𝐶(𝑠)(𝑠−3+𝐾𝑝)=𝐾𝑝𝑅(𝑠)

𝐶(𝑠)𝑅(𝑠)=𝐾𝑝𝑠−3+𝐾𝑝

𝐾𝑝>3

Piece Job

4.3 Time constant

Piece Job
𝜏 First-order time constant: how fast the output converges (63% of the way in one 𝜏).

How we reached it: pole, stability, and time constant

The denominator of the closed loop is 𝑠 −3 +𝐾𝑝 =𝑠 +(𝐾𝑝 −3). Its root:

𝑠+𝐾𝑝−3=0⟹𝑠=3−𝐾𝑝

3−𝐾𝑝<0⟹𝐾𝑝>3

𝑠+(𝐾𝑝−3)↔𝑠+1𝜏⟹1𝜏=𝐾𝑝−3⇒𝜏=1𝐾𝑝−3

So every unit of 𝐾𝑝 above 3 buys speed: larger 𝐾𝑝 → smaller 𝜏 → faster response in the ideal model.

Sanity check with the lecture's numbers:

𝐾𝑝 𝑐𝑠𝑠 =𝐾𝑝/(𝐾𝑝 −3) 𝑒𝑠𝑠 =1 −𝑐𝑠𝑠

Pattern: bigger 𝐾𝑝 squeezes the error toward 0 but never reaches it — the motivation for integral action in Part 5.

4.5 Why not crank 𝐾𝑝 to infinity?

  1. Noise sensitivity — huge gain turns tiny sensor noise into large control jumps.
  2. Actuator saturation — a motor driver cannot supply unlimited voltage/torque; the ideal formula assumes it can.
  3. Delays & unmodelled dynamics — real motors are not perfect first-order systems; high gain on an imperfect model triggers oscillation or instability.
  4. Robustness trade-off — a gain tuned to one exact model may fail when reality drifts from the model.

Conclusion of the case study: P alone stabilizes this plant but can never zero the step error — which is exactly the problem the integral term solves next.

Part 5 — PI Control

The PI controller adds a memory to the proportional muscle. Proportional action reacts to the error right now; integral action accumulates the error over time, so any persistent error keeps growing the command until it is eliminated.

5.1 The controller

𝐻𝑐(𝑠)=𝐾𝑝+𝐾𝐼𝑠=𝐾𝑝𝑠+𝐾𝐼𝑠

Symbol Name Job
𝐾𝑝 Proportional gain Reacts to the present: pushes proportionally to current error.
𝐾𝐼 Integral gain Reacts to the past: weights the accumulated error history.
1/𝑠 Integrator (Laplace) The mathematical memory: accumulation in time = division by 𝑠 in the Laplace domain.
𝐾𝑝𝑠 +𝐾𝐼 Combined numerator The form actually used inside the algebra (one fraction instead of two).

Plant under study: 𝐺(𝑠) =3𝑠+3 — pole at −3 (stable) and DC gain 33 =1, a well-behaved stand-in for a motor.

Part 6 — PID Control

6.1 Why add derivative action?

Integral action erases steady-state error, but its accumulated history makes it slow to react to sudden changes. Derivative action adds anticipation: it looks at how fast the error is changing and resists rapid motion, acting as a damper.

𝑢𝐷(𝑡)=𝐾𝑑𝑑𝑒(𝑡)𝑑𝑡

Symbol Job
𝐾𝑑 Derivative gain — how strongly the controller reacts to error trend.
𝑑𝑒𝑑𝑡 Rate of change of error — positive means the gap is growing, negative means it is closing.
The D-term's built-in weakness

Derivatives amplify high-frequency noise: a tiny but fast jitter in the sensor reading produces a large 𝑑𝑒/𝑑𝑡, so a noisy measurement can shake the actuator. That is why production controllers filter the derivative path.

6.2 The full PID controller

𝐻𝑐(𝑠)=𝐾𝑝+𝐾𝑖𝑠+𝐾𝑑𝑠

𝑢(𝑡)=𝐾𝑝𝑒(𝑡)+𝐾𝑖∫𝑡0𝑒(𝜏)𝑑𝜏+𝐾𝑑𝑑𝑒(𝑡)𝑑𝑡

Term What it reads Job in the command
𝐾𝑝 𝑒(𝑡) The error now Proportional muscle: instant response sized to the current gap.
𝐾𝑖∫𝑡0𝑒(𝜏) 𝑑𝜏 The error accumulated so far Memory: a persistent error keeps inflating the command until it dies. 𝜏 is a dummy variable sweeping 0 →𝑡 — integration "counts" all past errors.
𝐾𝑑𝑑𝑒𝑑𝑡 The error's trend Damper: brakes the approach if the error is closing fast, anticipating overshoot.

P Reacts to the present error Leaves steady-state error; too much gain → oscillation.

Tuning philosophy

The goal is to balance the three effects — never to maximize any single gain.

6.3 How are the gains selected?

There is no universal triple (𝐾𝑝,𝐾𝑖,𝐾𝑑) — the right values depend on the plant, its behavior, and its limits. The three routes: simulation (model + disturbances, test many combos), manual tuning (adjust on the real system, carefully), and automatic tuning (algorithms pick gains from the measured response). Whichever route, you watch these specs:

Monitored spec What it measures
Rise time Time to first reach a large fraction of the target.
Overshoot How far the output exceeds the target.
Settling time Time until the output stays within a band around the target.
Steady-state error The leftover gap after settling.
Stability Does the response converge, or do oscillations grow?
Implementation

PID can live in analog hardware (op-amp circuits) or software — in a microcontroller it is simply the same arithmetic repeated every sampling period, which is exactly what Part 7 formalizes.

Part 7 — Discrete-Time PID in Code

A microcontroller cannot integrate or differentiate continuously — it samples the system every 𝑇𝑠 seconds and approximates both operations with arithmetic on samples. Let 𝑒[𝑘] be the error at sample 𝑘.

7.1 The two approximations

∫𝑡0𝑒(𝑡)𝑑𝑡≈𝑇𝑠𝑘∑𝑖=0𝑒[𝑖]

7.3 The algorithm, one cycle at a time

  1. Read the current sensor measurement 𝑐.
  2. Get the reference 𝑟.
  3. Compute 𝑒 =𝑟 −𝑐.
  4. Add the current error to the integral accumulator.
  5. Compute the difference 𝑒[𝑘] −𝑒[𝑘 −1].
  6. Combine P + I + D into the raw command.
  7. Clamp the result to the actuator's valid range.
  8. Save the current error for the next cycle.
  9. Send the bounded command to the motor driver.

7.4 Teaching example in C++

float Kp = 1.0f, Ki = 0.1f, Kd = 0.05f;
float integral = 0.0f, previousError = 0.0f;

const float Ts   = 0.01f;   // 10 ms sampling period
const float uMin = 0.0f;    // minimum PWM duty cycle
const float uMax = 1.0f;    // maximum PWM duty cycle

float pid(float reference, float measured) {
    float error = reference - measured;         // step 3
    integral += error * Ts;                     // step 4  (software integrator)
    float derivative = (error - previousError) / Ts;  // step 5

    float u = Kp * error + Ki * integral + Kd * derivative;  // step 6

    if (u > uMax) u = uMax;                     // step 7 (clamping)
    if (u < uMin) u = uMin;

    previousError = error;                      // step 8
    return u;                                   // step 9
}
// Call pid() at a fixed rate (every 10 ms), with fresh encoder data.
Assumptions & production caveats

The code assumes it is called at a fixed rate — if the real interval varies, the integral and derivative must use the actual elapsed time. Production controllers also add derivative filtering and proper anti-windup logic (so the accumulator does not keep growing while the actuator is saturated).

Part 8 — Robot Structure Math (Degrees of Freedom)

Control tells the robot how to move; structure decides which movements are possible at all. The math here counts independent variables.

Definition

Degrees of freedom (DOF) = the number of independent variables needed to describe the motion or configuration of a system. For a joint that variable is an angle 𝜃 or a displacement 𝑑; for a free end effector it is position plus orientation.

Part 9 — Grübler's Formula for Mobility

Grübler's formula estimates a mechanism's mobility — its total number of independent motions — from its parts. The logic: count the motion every free link would have, then subtract what the joints lock away.

𝐹=𝑑(𝑁−1−𝐽)+𝐽∑𝑖=1𝑓𝑖

Symbol Name Job
𝐹 Mobility The mechanism's total independent DOF — how many independent inputs move it deterministically.
𝑑 Space dimension DOF of one completely free rigid link: 𝑑 =3 planar (𝑥,𝑦,𝜃), 𝑑 =6 spatial.
𝑁 Number of links Includes the ground link — it counts even though it never moves, because moving links are 𝑁 −1.
𝐽 Number of joints Physical connections; a 2-DOF joint still counts as one joint.
𝑓𝑖 DOF of joint 𝑖 How many relative motions joint 𝑖 permits (revolute =1, cylindrical =2, spherical =3…).
∑𝑓𝑖 Total joint freedom Sum over all joints — the motion the joints return to the mechanism.
How we reached it: the formula itself from constraint counting

Free motion before constraints. With 𝑁 links (1 of them ground), the 𝑁 −1 moving links each have 𝑑 free motions:

free motion=𝑑(𝑁−1)

Motion removed by each joint. In a 𝑑-dimensional space, two connected links have 𝑑 possible relative motions, but a joint of freedom 𝑓𝑖 permits only 𝑓𝑖 of them — so joint 𝑖 removes 𝑑 −𝑓𝑖 relative motions. Over all 𝐽 joints:

removed=𝐽∑𝑖=1(𝑑−𝑓𝑖)=𝑑𝐽−𝐽∑𝑖=1𝑓𝑖

Subtract:

𝐹=𝑑(𝑁−1)−(𝑑𝐽−∑𝑓𝑖)=𝑑(𝑁−1)−𝑑𝐽+∑𝑓𝑖

Exactly the lecture's intuition: possible motion before constraints − motion blocked by joints = mobility.

Example 1: planar three-joint open-chain arm

A planar arm with three revolute joints:

  • 𝑑 =3 (planar world)
  • 𝑁 =4 — three moving links plus the ground
  • 𝐽 =3, each revolute joint 𝑓𝑖 =1, so ∑𝑓𝑖 =1 +1 +1 =3

Substitute:

𝐹=3(4−1−3)+3=3(0)+3=3

Meaning: three independent motions — so with one motor per joint, three motors fully control the arm.

Example 2: planar four-bar linkage

Both ends connected to the ground:

  • 𝑑 =3, 𝑁 =4 (three moving links + ground), 𝐽 =4, each 𝑓𝑖 =1 → ∑𝑓𝑖 =4

Substitute:

𝐹=3(4−1−4)+4=3(−1)+4=1

Meaning: one degree of freedom. Move the input link and every other part must follow deterministically — so one motor drives the whole mechanism. Adding a second uncoordinated motor would force two incompatible motions into the same constrained loop → internal stress or jamming.

Practical procedure for mobility problems

  1. Sketch the mechanism and mark the fixed ground/base.
  2. Count all links including the ground → 𝑁.
  3. Count every joint → 𝐽 (a 2-DOF joint is still one joint, with 𝑓𝑖 =2).
  4. Decide planar (𝑑 =3) or spatial (𝑑 =6).
  5. Add the joint freedoms → ∑𝑓𝑖.
  6. Substitute into Grübler's formula.
  7. Sanity-check the result against the actual geometry and loops.
The ground link trap

Forgetting to include the base in 𝑁 is the most common exam mistake — the formula's −1 term exists precisely to remove the ground from the moving count while still counting it as a link.
