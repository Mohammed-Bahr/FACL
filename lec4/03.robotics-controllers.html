Learning goal

Understand how a robot measures what it is doing, compares that measurement with a target, corrects its behavior with a controller, and how the robot's mechanical joints determine the motions it can perform.

A robot needs two kinds of reasoning:

  1. Control: What should the motors do so the robot reaches the commanded position or speed?
  2. Mechanics: What motions are physically possible for the robot, and how many independent motions can we control?

The control part connects a reference (the target) to a controller, a plant (the motor or robot), and usually a sensor that measures the result. The mechanical part describes the robot as links connected by joints, ending in an end effector such as a gripper or screwdriver.

Think of the full loop this way: “I want this motion” → calculate the error → command the motors → measure the actual motion → correct the remaining error.~

Part 1: Control Systems and Feedback

What is a control system? A control system is a set of components that makes a system behave according to a desired objective.

  • Reference𝑟(𝑡):, the desired value, such as a target angle or speed.
  • Plant: the physical system being controlled, such as a motor, robot joint, or complete robot.
  • Controller: calculates a control action from the error.
  • Actuator: turns the control command into physical action. A motor driver and motor are common examples.
  • Sensor: measures the actual output, such as position or speed.
  • Output𝑐(𝑡):, the actual measured or produced result.
  • Error𝑒(𝑡):, the difference between what is desired and what is measured.

In the lecture, the motor's PWM duty cycle, 𝛼, is an example of a control command. The controller changes 𝛼 to affect the motor's speed.

Open-loop versus closed-loop control

Feature Open loop Closed loop
Feedback Does not measure the result for correction Measures the result and uses it to correct behavior
Main idea “Send a command and assume it worked” “Send a command, measure, compare, and correct”
Hardware/software Can be simpler and cheaper Needs sensing and control logic
Main weakness Disturbances and component changes can create errors that remain unnoticed Poor tuning, noisy measurements, delays, or bad design can make the loop perform poorly or become unstable
Typical use Simple tasks in predictable conditions Tasks needing accuracy despite changing loads or disturbances

Analog for better understand Suppose you apply a fixed PWM duty cycle to a motor. If the load becomes heavier, the motor may slow down.

  • In open loop, the controller does not notice the speed change, so it continues sending the same command.
  • In closed loop, a speed sensor detects that the motor is slower than the reference. The controller increases the command to reduce the error.

The error signal

For unity feedback, the error is𝑒(𝑡)=𝑟(𝑡)−𝑐(𝑡)

  • 𝑟(𝑡) is the reference.
  • 𝑐(𝑡) is the output measurement.
  • 𝑒(𝑡) is the error sent to the controller.

Three useful cases:

  • If 𝑒 >0, the measured output is below the reference.
  • If 𝑒 <0, the measured output is above the reference.
  • If 𝑒 =0, the reference and measured output are equal at that instant.

For the motor example, a positive error may cause the controller to increase PWM duty cycle 𝛼, a negative error may cause it to decrease PWM duty cycle 𝛼.

The exact action depends on how the plant and controller are defined, but the objective is to drive the error toward zero.

What does negative feedback mean?

The output is subtracted from the reference at the summing point: 𝑒 =𝑟 −𝑐.
This is called negative feedback. It does not mean that the system's output must be negative, it describes the sign used when feeding the measured output back into the comparison.

Why use feedback?

A properly designed feedback loop can improve:

  1. Accuracy: it corrects deviations between the reference and output.
  2. Disturbance rejection: it can compensate for changes in load or plant parameters.
  3. Time response: it can make the output respond more effectively to a command.
  4. Stability: with suitable controller design, feedback can stabilize a plant that is unstable on its own.
These benefits are not automatic. Feedback can also amplify sensor noise or cause oscillation if the controller is badly tuned.
Why can open-loop accuracy drift?
  • Motor resistance, magnetic strength, friction, load, and other physical properties can change with time or operating conditions.
  • A fixed command-to-output calibration (معايرة) may then become inaccurate.
An Open-loop system may need recalibration. Closed-loop control measures the result and attempts to compensate for these changes automatically.

4.5 Why not make 𝐾ₚ extremely large?

A large proportional gain can reduce error and improve the ideal response speed, but practical systems have limits:

  1. Noise sensitivity: a high gain can make small measured errors or noise create large control changes.
  2. Actuator saturation: a motor driver cannot supply unlimited voltage or torque.
  3. Delay and unmodelled dynamics: real motors and electronics are not perfect first-order models. A high gain can trigger oscillations or instability.
  4. Robustness trade-off: a design that works well for one exact model may behave badly when the real plant differs from the model.

زيادة 𝐾𝑝 معناها إن الكنترولر بيرد بقوة أكبر على الخطأ. ده ممكن يخلّي الاستجابة أسرع، لكن مش معناه إننا نزودها للآخر لأن الموتور له حدود، والسنسور فيه noise، وأي تأخير في النظام ممكن يحوّل التصحيح القوي لاهتزاز مستمر.

This limitation motivates integral action, which can remove steady-state error without requiring an infinitely large proportional gain.

  • Proportional action (P): reacts to the current error.

Part 6 PID Control

6.1 Why add derivative action?

Integral action is useful because it eliminates steady-state error, but its accumulated history can make the controller slow to react to a sudden change.
- الـ I يجمع الخطأ عبر الزمن ويقدر يزيل الخطأ النهائي الثابت.

Derivative action (D) reacts to how quickly the error is changing. It can anticipate a rapid movement toward or away from the target and add damping.𝑢𝐷(𝑡)=𝐾𝑑𝑑𝑒(𝑡)𝑑𝑡

  • 𝐾𝑑: Derivative Gain.
  • 𝑑𝑒(𝑡)𝑑𝑡: معدل تغيّر الخطأ مع الزمن.
The derivative term has a major drawback: it is sensitive to high-frequency sensor noise. Even a small noisy change over a short interval can create a large derivative value.

6.2 The full PID equation



A PID controller combines all three actions:

𝐻𝑐(𝑠)=𝐾𝑝+𝐾𝑖𝑠+𝐾𝑑𝑠

In time-domain form, the ideal controller output can be written as

  • 𝐾𝑝: معامل بيتعامل مع خطأ الموضع الحالي.
  • 𝐾𝑖: معامل بيتعامل مع تراكم الخطأ بمرور الزمن.
  • 𝐾𝑑: معامل بيتعامل مع معدل تغيّر الخطأ.

Here 𝑢(𝑡) is the controller command sent toward the actuator, such as a requested motor-driver output or PWM duty cycle before limits are applied.

Part 7 Discrete-Time PID in Code

ال Discrete-Time PID in Code إزاي نحول متحكم PID لمعادلات وكود على الـ Microcontroller

عمليًا، نراقب عدة خصائص:
A microcontroller does not calculate continuous integrals and derivatives directly. It samples the system at discrete time instants and approximates these operations numerically.

7.1 Approximate integral and derivative

Let 𝑇ₛ be the fixed sampling period, and let 𝑒[𝑘] be the error at sample 𝑘. (الـ Sampling Period هو الزمن بين كل قراءتين متتاليتين للحساس وتنفيذ عمليتي التحكم.)

Integral approximation:

∫𝑒(𝑡)𝑑𝑡≈𝑇𝑠𝑘∑𝑖=0𝑒[𝑖]

Derivative approximation:

𝑑𝑒𝑑𝑡≈𝑒[𝑘]−𝑒[𝑘−1]𝑇𝑠

So a practical discrete PID expression is

𝑢[𝑘]=𝐾𝑝𝑒[𝑘]+𝐾𝑖𝑇𝑠𝑘∑𝑖=0𝑒[𝑖]+𝐾𝑑𝑒[𝑘]−𝑒[𝑘−1]𝑇𝑠

المعادلة بتقول إن current controller 𝑢[𝑘] ناتج عن ثلاثة أجزاء:

  • 𝐾𝑝𝑒[𝑘]: تأثير الخطأ الحالي.
  • 𝐾𝑖𝑇𝑠∑𝑒[𝑖]: تأثير الأخطاء المتراكمة.
  • 𝐾𝑑(𝑒[𝑘] −𝑒[𝑘 −1])/𝑇𝑠: تأثير سرعة تغيّر الخطأ.

7.2 Understand the algorithm step by step

At each control cycle:

  1. Read the current sensor measurement 𝑐.
  2. Obtain the reference 𝑟.
  3. Calculate 𝑒 =𝑟 −𝑐.
  4. Add the current error to the integral accumulator.
  5. Calculate the difference between the current and previous error.
  6. Combine P, I, and D into the raw controller output.
  7. Limit the result to the actuator's valid range.
  8. Save the current error for the next iteration.
  9. Send the bounded command to the motor driver.

7.3 Example C++ implementation

This version explicitly uses the sampling period 𝑇𝑠, so 𝐾𝑖 and 𝐾𝑑 are interpreted as continuous-time gains. It is meant as a simple teaching example, production controllers may require filtering and more careful anti-windup logic.

float Kp = 1.0f,
float Ki = 0.1f,
float Kd = 0.05f,

float integral = 0.0f,
float previousError = 0.0f,

const float Ts = 0.01f,       // 10 ms sample period
const float uMin = 0.0f,       // minimum PWM duty cycle
const float uMax = 1.0f,       // maximum PWM duty cycle

float pid(float reference, float measured) {
    const float error = reference - measured,

    integral += error * Ts,
    const float derivative = (error - previousError) / Ts,

    float u = Kp * error + Ki * integral + Kd * derivative,

    // Constrain the command to the actuator's valid range.
    if (u > uMax) u = uMax,
    if (u < uMin) u = uMin,

    previousError = error,
    return u,
}

// Call pid() at a fixed rate (every 10 ms here),
// using the latest encoder measurement each time.

The code assumes it is called at a fixed rate. If the actual time between calls varies significantly, the integral and derivative approximations should account for the actual elapsed time.

Part 8 Robot Mechanical Structures

Control tells the robot how to move, robot structure tells us which movements are mechanically possible.

8.1 Degrees of freedom (DOF)

Degrees of freedom are the number of independent variables required to describe the motion or configuration of a system.

For a joint, the independent variable may be an angle or a displacement. For an end effector moving in space, we describe both its position and its orientation.

8.2 Primitive joints

The lecture identifies revolute and prismatic joints as the two primitive joint types.

Joint type Allowed motion Typical parameter(s) Joint DOF
Revolute Rotation about one axis Angle 𝜃 1
Prismatic Linear sliding along one axis Displacement 𝑑 1
Cylindrical Rotation and sliding along the same axis 𝜃 and 𝑑 2
Universal Rotation about two perpendicular axes Two angles 2
Spherical Rotation about three axes, like a ball joint Three angular variables 3

A prismatic displacement is often measured relative to a chosen reference position. It can be positive or negative depending on the chosen coordinate direction.

8.3 Links, joints, and end effectors

A robot can be represented as a chain or mechanism made from:

  • Link: a rigid body between joints.
  • Joint: a connection that permits specific relative movement between links.
  • End effector: the part at the end of the robot that acts on the environment, such as a gripper, hand, or screwdriver.
  • Ground/base: the fixed reference link to which the robot is attached.
For example, روبوت يحمل مفكاً لربط مسمار المفاصل تحرك الأداة وتوجهها، والوصلات تربط هذه المفاصل، والمفك نفسه هو الـ End Effector الذي يقوم بالمهمة الأساسية.

Grübler's formula estimates the number of independent motions (mobility or DOF) of a mechanism from its links and joints.

𝐹=𝑑(𝑁−1−𝐽)+𝐽∑𝑖=1𝑓𝑖
To avoid a notation conflict, these notes use 𝑑 for the dimensionality of the motion space in Grübler's formula. Some resources using 𝑚 for this quantity, but the earlier section also uses 𝑚 for end-effector task DOF.
where:

  • 𝐹 = mobility, or the mechanism's total independent DOF.
  • 𝑑 = DOF of a completely free rigid link in the space being considered:
    • 3 for planar motion,

  • 𝑁 = total number of links, including the ground link.
  • 𝐽 = number of joints.

A practical procedure for solving mobility questions

  1. Sketch the mechanism and mark the fixed ground/base.
  2. Count all links, including the ground, to obtain 𝑁.
  3. Count every joint to obtain 𝐽, a joint with two DOF is still one joint, but its 𝑓𝑖 value is 2.
  4. Identify whether the mechanism is planar (𝑑 =3) or spatial (𝑑 =6) for the formula being used.
  5. Add the joint DOF values to obtain ∑𝑓ᵢ.
  6. Substitute into Grübler's formula.
  7. Check whether the result makes sense for the actual geometry, loops, and constraints.
