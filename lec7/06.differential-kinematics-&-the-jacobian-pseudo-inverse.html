The Big Picture: Why Differential Kinematics & 𝐽+? In the previous lectures, we built the foundation of robot motion:

  • 04.kinematics: Position Kinematics answered: "If my joints are at angles 𝑞, where is my hand 𝑝?" (𝑝 =𝑓(𝑞)), and "To place my hand at 𝑝, what joint angles do I need?" (𝑞 =𝑓−1(𝑝)).
  • 05.Robot Coordinate Transformations & Differential Kinematics: We learned how to transform coordinate frames using Homogeneous Transformations (𝑇𝑛0) and introduced the Jacobian Matrix (𝐽), which relates small joint changes to small hand displacements: 𝛿𝑝 =𝐽𝛿𝑞.
The Engineering Problem of This note:

In real life, robots do not "teleport" between positions. We don't just send target positions to the motors we control velocities in real time:

Like saying : "Move the gripper smoothly to the right at 5 cm/s."

To do that, the controller must answer Given desired hand velocity ˙𝑝, what motor speeds ˙𝑞 must we command.

Since ˙𝑝=𝐽(𝑞) ˙𝑞, the obvious answer seems to be: ˙𝑞=𝐽−1 ˙𝑝But here is the catch:

  1. 𝐽 is almost never square (𝑚 ≠𝑛): Robots often have more joints than task dimensions (𝑛 >𝑚, redundancy) or fewer (𝑛 <𝑚). A non-square matrix has no regular inverse.
  2. Even when 𝐽 is square (𝑚 =𝑛), robots can hit singularities where det(𝐽) =0, causing 𝐽−1 to blow up to infinity!

Lecture 7 provides the full engineering solution:
Using Least Squares Optimization, the Moore-Penrose Pseudoinverse (𝐽+), and SVD (Singular Value Decomposition) to invert the velocity relationship safely, and finally plugging it into a closed-loop PID controller.

  • Singularity: Any configuration 𝑞 where 𝐽(𝑞) loses full rank (rank(𝐽) <min(𝑚,𝑛)).
  • Physical Meaning: Two or more columns of 𝐽 become collinear (linearly dependent).
    • The robot loses the ability to move in that specific Cartesian direction, no matter how fast the motors spin!
  • Manipulability Ellipsoid: If we feed the robot a unit sphere of joint velocities (‖˙𝑞‖ ≤1), the Jacobian maps it into an ellipsoid of possible Cartesian velocities.
    • Semi-axis lengths = singular values 𝜎𝑖.
    • Near a singularity, the ellipsoid collapses into a flat disk, indicating zero mobility along the collapsed axis.

2. 📐 Frame-to-Frame Transformations & DH Parameters

3. ⚖️ The Inverse Problem: Dimensions & Invertibility

Now we know that:
˙𝑥=𝐽(𝑞)˙𝑞This means given Joint Velocities, we calculate the End Effector Velocity. But in Robotics Control, we usually want the opposite!
The user tells the robot: "Move the End Effector toward this location."
We know the required motion of the End Effector, but we don't know how the Joints should move.

So We want to solve for joint velocities:
˙𝑝=𝐽˙𝑞⟹˙𝑞=𝐽−1˙𝑝

Let's inspect the dimensions: 𝐽 ∈ℝ𝑚×𝑛

  • 𝑚: Number of task coordinates (e.g. 𝑚 =6 for full 3D pose, or 𝑚 =2,3 for planar position).
  • 𝑛: Number of joints (motors).

The Three Cases:

  1. Square & Non-Singular (𝑚 =𝑛, det(𝐽) ≠0): Exactly one unique joint velocity vector achieves the task: ˙𝑞 =𝐽−1˙𝑝.
  2. Overdetermined / Tall Matrix (𝑚 >𝑛):
    • More task constraints than joints (e.g. a 2-joint arm trying to follow a 3D trajectory: 𝑚 =3,𝑛 =2).
    • Generally, no exact solution exists. The robot cannot achieve the desired velocity. We must find the ˙𝑞 that minimizes tracking error.
  3. Underdetermined / Wide Matrix (𝑚 <𝑛, Redundant Robot):
    • More joints than task constraints (e.g. a 7-DOF arm in 3D space: 𝑚 =3,𝑛 =7, or controlling 6D pose: 𝑚 =6,𝑛 =7).
    • Infinitely many solutions exist! The arm has redundancy (𝑛 −𝑚 >0). We must choose the single solution that minimizes motor effort (kinetic energy).

🧮 4. Least Squares & The Pseudoinverse (𝐽+)

When 𝑚 ≠𝑛 (non-square), an exact solution may not exist or may not be unique. We formulate an equivalent optimization problem to find the optimal joint velocity vector ˙𝑞∗ that minimizes the squared two-norm of the velocity error using Least Squares Optimization.

Why Does the Lecture Sometimes Prefer the Second Formula?

In robotics, you might have 7 Joints but request motion in 6 Dimensions (𝐽 :6 ×7).
If we use the first formula, we need to invert 𝐽𝑇𝐽, which is 7 ×7.
But if we use the second formula, we invert 𝐽𝐽𝑇, which is 6 ×6.

Inverting a 6 ×6 matrix is generally less computationally expensive than a 7 ×7. However, this doesn't mean the second formula is always numerically better; Numerical Stability is critical, which leads us to the next section.

5. 💎 SVD (Singular Value Decomposition): The Robust Approach

In practical robotics software, computing (𝐽𝐽𝑇)−1 directly can be dangerous. If the robot approaches a singularity, det(𝐽𝐽𝑇) ≈0, causing numerical explosion.

Singular Value Decomposition (SVD) provides the safest, most numerically stable way to compute 𝐽+.

==The SVD Decomposition:== Any real matrix 𝐽 ∈ℝ𝑚×𝑛 can be decomposed into:𝐽=𝑈𝑆𝑉𝑇

  • 𝑈 ∈ℝ𝑚×𝑚: Orthogonal matrix (𝑈−1 =𝑈𝑇)→ containing the eigenvectors of 𝐽𝐽𝑇 (𝑈−1 =𝑈𝑇):
    • Its columns 𝑢𝑖 are the left singular vectors, representing principal directions in Task Space.
  • 𝑆 ∈ℝ𝑚×𝑛: Diagonal matrix of singular values arranged in descending order: 𝜎1 ≥𝜎2 ≥⋯ ≥𝜎𝑟 ≥0.
    • They represent the gain/sensitivity along each axis.
  • 𝑉 ∈ℝ𝑛×𝑛: Orthogonal matrix (𝑉−1 =𝑉𝑇) → containing the eigenvectors of 𝐽𝑇𝐽 (𝑉−1 =𝑉𝑇):
    • Its columns 𝑣𝑖 are the right singular vectors, representing directions in Joint Space.

Computing 𝐽+ via SVD: 𝐽+=𝑉𝑆+𝑈𝑇Where 𝑆+𝑛×𝑚 is formed by replacing every non-zero singular value 𝜎𝑖 on the diagonal of 𝑆 with its inverse singular value 1𝜎𝑖: 𝑆+=⎡⎢ ⎢ ⎢ ⎢ ⎢ ⎢ ⎢ ⎢ ⎢ ⎢ ⎢ ⎢⎣1𝜎10001𝜎20001𝜎3000000⎤⎥ ⎥ ⎥ ⎥ ⎥ ⎥ ⎥ ⎥ ⎥ ⎥ ⎥ ⎥⎦(for 𝑚=3,𝑛=5)

⚠️ The Danger of Near-Singularities & Damped Least Squares (DLS)

What happens when the robot is near a singularity?

  • A singular value becomes tiny: 𝜎min =0.0001.
  • In 𝑆+, its inverse explodes: 1𝜎min =10,000!

A commanded hand speed of 1 cm/s commands the motors to spin at thousands of rad/s. This trips over-current alarms, burns motor drivers, or causes violent vibrations.

The Engineering Fix: Damped Least Squares (Levenberg-Marquardt)

Instead of minimizing only error, we penalize excessively large joint speeds:
min˙𝑞(‖˙𝑝−𝐽˙𝑞‖2+𝜆2‖˙𝑞‖2)𝐽+damped=𝐽𝑇(𝐽𝐽𝑇+𝜆2𝐼)−1

In SVD terms, every singular value reciprocal 1𝜎𝑖 is replaced by:
𝜎𝑖𝜎2𝑖+𝜆2

  • When 𝜎𝑖 is large: 𝜎𝑖𝜎2𝑖+𝜆2 ≈1𝜎𝑖 (normal tracking).
  • When 𝜎𝑖 →0: 𝜎𝑖𝜎2𝑖+𝜆2 →0 (smoothly limits motor speed to zero, sacrificing exact tracking for physical safety!).

6. 🔄 Closed-Loop Robot Control Architecture

Now we connect the math to the physical control loop. The robot takes high-level user commands and converts them into motor torques.

6.1 The Complete Step-by-Step Control Pipeline

  1. User Goal: User commands a reference pose 𝑝ref in Task Space.
  2. Feedback Sensing: Motor encoders measure actual joint angles 𝑞act.
  3. Forward Kinematics: The robot computes its current Cartesian position: 𝑝act =𝑓(𝑞act).
  4. Cartesian Error: 𝑒𝑝 =𝑝ref −𝑝act.
  5. Desired Cartesian Velocity: ˙𝑝cmd =𝐾𝑒𝑝.
  6. Differential IK via 𝐽+: Convert task velocity to required joint velocities:˙𝑞cmd=𝐽+(𝑞act)˙𝑝cmd
  7. Joint PID Controller: Generates motor voltages/currents 𝑢(𝑡) to eliminate joint tracking errors:𝑢(𝑡)=𝐾𝑝𝑒𝑞(𝑡)+𝐾𝑖∫𝑒𝑞(𝜏)𝑑𝜏+𝐾𝑑𝑑𝑒𝑞(𝑡)𝑑𝑡
  8. Actuation & Loop: Motors turn links → new 𝑞 is read → loop repeats at 500–1000 Hz.
